# 研究引擎重构计划（独立立项）

> 立项日期：2026-08-29
> 对象：`quant/assistant/research.py`（2590 行）、`quant/assistant/risk.py`（115 行）、`quant/scripts/run_under50_research.py`（506 行）
> 前置状态：git 仓库已建立（3 个提交）；全量测试 88 个用例 22.8s 全绿（`quant/logs/codex-runs/full-suite-20260829T013856.*`）

## 1. 背景与问题

`research.py` 当前一个文件承担六类职责（行号为 2026-08-29 实测）：

| 行号区间 | 职责 | 约行数 |
|---|---|---|
| 89–160 | 小工具函数（时间、数值、JSON 清洗） | ~70 |
| 160–520 | 数据加载与质量（`_load_asset`、`_scan_assets`、`_aggregate_quality`、复权/流动性检查） | ~360 |
| 521–817 | 技术面信号（趋势、回撤、相对基准、同类比较） | ~296 |
| 818–1109 | Qlib 训练与模型指标（`_run_qlib_stock_model` 等） | ~291 |
| 1110–1601 | 排队与 worker（`_queue_research`、`_start_background_worker`、`_refresh_data`） | ~490 |
| 1602–1839 | run 生命周期（写文件、状态心跳、过期清扫、文件锁） | ~237 |
| 1840–2375 | `run_research` 主编排 | ~536 |
| 2376–2590 | 对外只读 API（`get_current_snapshot`、`get_run_status`、通知） | ~215 |

派生问题：

1. **权重生成逻辑内嵌在主编排里**——ETF/基金路径的 `per_symbol = min(budget/候选数, max_single_weight)` 等权切分写死在 `run_research` 中，`risk.py` 只做约束校验，不做生成。想换"分数加权"等策略必须动 2000 行大文件。
2. **第二套 Qlib 训练代码**——`run_under50_research.py` 自带 Alpha158 + LGBModel 训练流程，与主路径重复，改一处漏一处。
3. **无回归安全网**——现有测试按模块打桩，没有"整条研究流程输出快照"的端到端锁定，重构无法证明行为未变。

## 2. 目标与非目标

**目标**

- G1：`research.py` 拆分为职责单一的模块，主文件降到 800 行以内，**行为零变化**。
- G2：权重生成独立为 `portfolio.py`，策略可插拔（默认策略 = 现行为）。
- G3：`run_under50_research.py` 与主路径共享 Qlib 数据集构建/训练层。
- G4：为未来能力（滚动重训、建议归因回看）留好接口，但本立项不实现。

**非目标（红线，本立项不做）**

- 不改 MCP 工具面（5 个工具的名称、参数 schema、返回结构）。
- 不改 `current.json` 对外字段。
- 不改任何风控参数与模型门槛数值（`assistant.yaml` 的 risk/gate 段）。
- 不触碰安全边界：不连券商、不自动下单、固定路径策略不变。

## 3. 阶段 0：快照回归测试（安全网，必须最先做）

**做法**

1. 在 `tests/fixtures/` 构造固定小型数据集：3 只股票 + 2 只 ETF + 2 只场外基金 + 510300 基准 CSV，日期截至固定日期，手工可核验。
2. 新建 `tests/test_research_snapshot.py`：
   - 复用 `AssistantStateMachineTests` 的 tmp-dir + patch 手法（临时目录必须在 `quant/tests/` 下，`fixed_path` 白名单）；
   - `_run_qlib_stock_model` 打桩返回固定 metrics + 固定 scores（Qlib 训练有随机性，编排层测试不训练真模型）；
   - 断言整条输出链：`status.json` 生命周期、manifest 结构、`rule_gates` 每个检查值、`decision_support.asset_paths` 三类路径的状态与权重、`current.json` 全字段。
3. 快照用"逐字段断言"而不是整个 JSON 字符串对比，失败时错误信息可读。

**验收**：快照测试在当前未重构代码上通过；输出与真实 08/26 完整运行的结构一致。此后它成为每个重构提交的门禁。

## 4. 阶段 1：行为保持的拆分（只移动，不修改）

目标结构（对应第 1 节行号区间）：

```
assistant/
  research.py      # 保留：工具函数 + run_research 编排 + run 生命周期（锁/心跳/清扫）  ← ~700 行
  data_layer.py    # 数据加载与质量（160–520 区间）                                    ← ~360 行
  signals.py       # 技术面信号（521–817 区间）                                        ← ~300 行
  qlib_model.py    # Qlib 训练与指标（818–1109 区间）                                  ← ~290 行
  queueing.py      # 排队/worker/刷新（1110–1601 区间）                                ← ~490 行
  read_api.py      # get_current_snapshot / get_run_status / 通知（2376–2590 区间）     ← ~215 行
  risk.py          # 不动
  portfolio.py     # 阶段 2 建壳
```

**纪律（每一条都是硬规则）**

1. 一个提交只移动一个函数组；函数体逐字不动（允许的改动仅限 import 行和跨模块调用的名字来源）。
2. `research.py` 顶部临时保留 `from .data_layer import *` 式兼容层，让所有旧名字继续可用——测试与调用方零改动；兼容层在阶段 1 结束时评估是否移除。
3. 每个提交后依次跑：快照测试 → `tests.test_assistant` → 全量套件（按 AGENTS.md 分离式运行，复用 `logs/codex-runs/run-full-suite.ps1`）。
4. 任何一步红了：`git revert` 回上一个绿提交，不现场修补。

**验收**：`research.py` ≤ 800 行；全部测试绿；快照输出与阶段 0 基线一致；MCP stdio 集成测试绿。

## 5. 阶段 2：权重生成模块 `portfolio.py`

1. 抽出内嵌逻辑：`build_target_weights(candidates, asset_type, risk_config, previous=None)` ——输入带分数的候选列表，输出 `enforce_target_weights` 可直接消费的 requested 字典；默认策略 `equal_score` 精确复刻现行为（候选数切分预算 + `min(max_single_weight)`）。
2. 增加一个可选策略 `score_weighted`（按分数比例加权后裁剪到上限），**默认仍为 `equal_score`**，仅在配置中显式切换。
3. 单元测试覆盖边界：零候选、单候选超单票上限、类别敞口顶格、换手超限回退现金。
4. **验收**：`equal_score` 下快照测试输出与基线完全一致；`risk.py` 的 `enforce_target_weights` 不做任何语义修改。

## 6. 阶段 3（可选）：Qlib 训练层合并

- 把数据集构建 + handler + LGBModel 训练的公共部分抽到 `qlib_model.py`，`run_under50_research.py` 改为调用方。
- under50 的账户模拟、参数扫描逻辑不动。
- 验收：`run_under50_research.py` 在固定配置下产出的指标与重构前同分布（容差比较，训练本身有随机性）；主路径快照不受影响。
