# 数据守卫说明（价格刻度防线）

## 背景

2026-08-27 起抓取源混入错档行情（他票/指数行、错刻度行），约 2750 只股票 8-28~9-02 附近被污染。
个例：603826 在 8-28 由 16.22 跳到 39.29（错一倍多），质检全绿放行，研究曾据此给出 2 成仓位，实为脏数。

## 三道防线

1. 入库验货（quant/scripts/price_guards.py + fetch_utils.merge_daily_frames 钩子）
   逐行相对上一保留行判定：隔夜跳变超 30% 且向上必隔离；向下需同时满足除权三条件（价格因子 0.25~1、成交量反比、成交额连续）否则隔离；
   跨 10 天以上的日历断档视为停牌复牌，不判定、只记录。隔离行写入 data/stocks/quarantine/<symbol>.quarantine.csv。

2. 同花顺裁判（quant/scripts/price_guards.py fetch_ths_daily/ths_crosscheck/ths_patch_recent，data_source 疑似触发）
   本地验货报警且单帧行数>=20 才拉同花顺近 5 天抽查，分歧超 20% 按裁判价修复；平时零新增请求。
   注意：同花顺为不复权口径，回填必须按文件既有复权刻度换算（锚点因子），成交量注意手/股单位（文件内是多少就是多少，以锚点对齐）。

3. 消费侧熔断（quant/assistant/data_layer._price_consistency_check，与入库同一套规则）
   脏标的进 failed_assets、不计 eligible、不给目标权重，decision_support 标注 data_quarantined。

## 离线体检与修复脚本

- quant/scripts/scan_price_health.py：全市场只读扫描（默认只看近 250 行），输出 suspects/by_date 到 quant/logs/codex-runs/scan-*.json。
- quant/scripts/mass_repair_ths.py：按扫描名单批量回填（锚点复权因子+成交量单位对齐），先备份原文件到 quarantine。
- quant/scripts/fill_holes.py + find_holes.py：补 8-28~9-02 缺洞（只补同花顺有的日子，停牌不动）。
- quant/scripts/repair_symbol_ohlc.py：单只修复（603826 专用版，已验证）。
- quant/scripts/boundary_check.py：验收所有修复文件的近期最大隔夜跳变。

## 测试

quant/tests/test_market_data.py::PriceGuardsTests：干净历史零隔离、错档段隔离、除权保留、停牌保留、隔离落盘、合并钩子。
跑法：python -m unittest discover -s tests -p test_market_data.py（本机无 pytest，用 unittest）。

## 已知局限

- 整段均匀错刻度且无跳变、无量额背离的，离线规则看不见，只能靠抓取时同花顺抽查。
- 603729/603721 类历史多刻度混编文件未自动重建（超出本次范围），质检熔断覆盖其不产出权重。
